# FOCUS — صفحة واحدة تحكم المحفظة

> الحالة: **مسودة قرار** — وفق المرحلة 1 من خطة الإصلاح، اختيار التركيز قرار مالك.
> ما دونها هو توصية الخطة (C ثم B) موثقة هنا لاعتمادها أو تعديلها.

## نحن نبني

**أداة طبيب واحدة (Option C)**: مسار ذهبي واحد — صورة وصفة/تقرير طبي عربي
→ OCR/HTR → تصحيح لغوي → عرض وتصحيح بشري → حفظ آمن محلي → بيانات تدريب.

## لـ

الأطباء والممارسين العرب الذين يتعاملون مع وثائق مكتوبة يدويًا ومطبوعة.

## ونقيسه بـ

| المقياس | الهدف |
|---|---|
| CER على المكتوب يدويًا | < 15% |
| دقة المصطلحات الطبية | الأعلى الممكن، مقيسًا على benchmark منشور |
| زمن أول نتيجة | < 60 ثانية |
| عودة المستخدم في اليوم التالي | 3/5 في اختبار 5 أطباء (المرحلة 4) |

## لماذا C ثم B (وليس A: المنصة)؟

- لا مستخدمين = لا بيانات تصحيح = لا أصل تنافسي.
- الأصل الحقيقي للخندق هو بيانات HTR العربية الطبية المصححة بشريًا (B)،
  ولا تتراكم إلا عبر منتج يُستخدم يوميًا (C).
- المنصة (A) بدون منتج ناجح = متحف تقنيات.

## ما يعنيه هذا عمليًا (باختصار حاكم)

1. كل ما خارج المسار الذهبي = مؤجل (لا إلغاء — تأجيل موثق).
2. UI واحد للمسار (اختيار من Gradio/PyQt6/Next.js) والبقية تُجمَّد.
3. لا ميزة جديدة بدون قياس benchmark يثبت تحسنها.
4. Benchmark من 200 صورة مجهولة الهوية + نشر النتائج = أول دليل خارجي.
