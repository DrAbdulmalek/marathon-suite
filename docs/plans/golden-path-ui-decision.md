# قرار واجهة المسار الذهبي الواحدة (S2-T1) — توصية واحدة مسببة

> التاريخ: 2026-10-08 | التزام العقد: «قرار واجهة قبل كود» + هيكل أدنى قابل للعكس فقط.
> القيد الحاكم من FOCUS.md: LOCAL_ONLY، أول نتيجة < 60 ثانية، صيانة وكيل منخفضة، طبيب عربي مستخدم.

## المقارنة (معايير العقد الستة)

| المعيار | Gradio | PyQt6 | Next.js |
|---|---|---|---|
| العمل دون إنترنت (تثبيت طبيب محلي) | ✅ localhost كامل | ✅ أصلٍ بدون خادم | ⚠️ يتطلب خادم node محلي |
| LOCAL_ONLY (إثبات صفر حزم صادرة) | ✅ أسهل إثباتًا (عملية بايثون واحدة) | ✅ أسهل (بلا مقابس استماع) | ❌ أصعب إثباتًا (طبقتان + مقابس) |
| زمن أول نتيجة (< 60 ثانية) | ✅ أسرع مسار للنموذج الأولي | ⚠️ بناء حزمة لكل نظام | ⚠️ طبقة API إضافية |
| تجربة الطبيب (RTL، خط كبير، مراجعة سريعة) | جيدة (مكونات جاهزة + تخصيص CSS) | ممتازة أصلًا | ممتازة لكن بكلفة بناء أعلى |
| منحنى صيانة الوكيل | ✅ ملف بايثون واحد يكفي للبداية | ❌ حزم/توقيع/توزيع | ❌ مستودعان منطقيان |
| التكامل مع ocr-core (بايثون) | ✅ استيراد مباشر | ✅ استيراد مباشر | ❌ عبر HTTP فقط |

## التوصية: **Gradio — محلي أولًا (localhost فقط)**

**المبررات الثلاث الحاسمة:**
1. **إثبات LOCAL_ONLY هو شرط معماري لا ميزة** — عملية بايثون واحدة تجعل اختبار S2-T4
   (اعتراض المقابس) صادقًا ومحكمًا؛ مع Next.js يصبح الإثبات أضعف طبقيًا.
2. **أقصر طريق لأول نتيجة < 60 ثانية** في اختبار الأطباء (المرحلة 4) — لا بناء حزم ولا خادم.
3. **أقل تكلفة صيانة وكيل** — الهيكل الأدنى المنفذ (omni: `tools/golden_path/`) ملف واحد قابل للنمو،
   مع باب عودة مفتوح: إذا فشل Gradio في تجربة الأطباء، القرار يُعاد ويُرحَّل الـ UI
   (العقد نفسه قابل للتراجع — واجهة عرض لا تحفظ حالة).

**متى يُعاد القرار؟** بعد المرحلة 4 فقط: إذا سجل 3/5 أطباء فأكثر قصور تجربة عرض/تصحيح
لا يمكن إصلاحه بمكونات Gradio المخصصة.

## الهيكل الأدنى (منفذ كفرع قابل للعكس — انظر PR ‏omni ‏[skeleton])

`omni-medical-suite/tools/golden_path/ui_app.py` — ثلاث خطوات فقط (رفع صورة →
نتيجة OCR عبر ocr-core → حقل تصحيح + حفظ محلي)، ربط محرك عبر واجهة، بلا أي
نداء شبكة خارجي، مع رفض الربط على غير 127.0.0.1 افتراضيًا.
