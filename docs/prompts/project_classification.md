**النقطة الحاسمة**: البرومبت نفسه يقول "لا دمج بدون evidence". أنا أُضيف: **"لا دمج بدون حسم الترخيص أولًا"**.

### 2. ما الذي يجب أن تسأل نفسك قبل تشغيل البرومبت

البرومبت سيمرّ عبر M-01 → M-08 وقد ينتج "ADOPT" لـ `It's a Plan` أو `Jina-OCR-v1`. **هذا سيكون خطأً معماريًا** إن لم تحسم:

- **هل `omni-medical-suite` مشروع تجاري الآن أو مستقبلي؟**
  - إن **نعم** → `Jina-OCR-v1` **مرفوض من البداية**. لا حاجة لتدقيقه.
  - إن **لا** → يمكن تقييمه بحثيًا.

- **هل ستوزّع `omni-medical-suite` للخارج؟**
  - إن **نعم** → `It's a Plan` (AGPL) **خطر تلويث**. يُقيَّم بحذر شديد.
  - إن **لا** (استخدام داخلي فقط) → AGPL لا يؤثر على مشروعك.

**البرومبت يفترض أن هذه القرارات غير محسومة**. لكن الحقيقة: **يجب حسمها قبل M-01**، لأنها تُغيّر نتائج M-04 و M-07 كليًا.

### 3. تحسينان مطلوبان في البرومبت

**أ. أضف M-00.5 — License Decision Gate**

قبل M-01، يحتاج المشرف أن يجيب:

```yaml
project_classification:
  commercial_intent: yes | no | undecided
  distribution_intent: yes | no | internal_only
  will_redistribute_binaries: yes | no

# Rules:
# - If commercial_intent=yes AND project=Jina-OCR-v1 → REJECT immediately
# - If distribution_intent=yes AND project=It's-a-Plan → HIGH RISK, needs legal review
# - If internal_only AND Apache/MIT → proceed
```

بدون هذه البوابة، البرومبت سيُجري تدقيقًا مكلفًا على مشاريع محسومة مسبقًا.
